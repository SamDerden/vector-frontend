# Вектор — фронтенд по утверждённой главной странице

**Что готово:** самостоятельный Next.js-проект с редактируемой главной страницей, возрастными карточками, выбором трека, динамической диагностикой, шестью уточняющими вопросами из API, результатами и рефлексией. Внешний вид основан на согласованном изображении; это **первый проход**, не точная пиксельная копия.

## Запуск
1. Установить Node.js 20+.
2. `npm install`
3. Скопировать `.env.example` в `.env.local` и указать URL бэкенда.
4. Запустить бэкенд отдельно на `http://localhost:3000` с рабочей PostgreSQL, миграциями, каталогом и настройками AI.
5. `npm run dev` — фронтенд откроется на `http://localhost:3001`.

Если API работает на другом порту, изменить `NEXT_PUBLIC_API_BASE_URL`. На бэкенде должен быть разрешён CORS для `http://localhost:3001`, включая `X-Session-ID`.

## Что не обещаем
- Это не замена существующего фронтенда разработчика; это отдельный стартовый проект.
- Маскоты и школьники используются как **отдельные растровые фрагменты** согласованных референсов. Полностью редактируемые векторные персонажи пока не созданы.
- Нет выдуманных профилей или рекомендаций: контент приходит из API.
- Статистика на главной 100+/50+/30+/20+ — числа из согласованного изображения, **не проверенные реальные данные каталога**. Перед публикацией сверить.
- В каталоге бэкенда вопросы 1–5 классов обозначены как «мок-версия» и содержат вопросы о профессиях; это **противоречит согласованной методологии 1–4**. До релиза нужно согласовать исправление с методологом и бэкендом. Фронтенд сейчас отображает ответ API, не скрывая этот конфликт.
- Результаты 1–4 пока не имеют отдельного утверждённого backend-формата интересов; вместо выдуманных интересов показано предупреждение. Нужно согласовать API-контракт.
- Диагностический блок поддерживает выбор нескольких вариантов; точные правила одиночного/множественного выбора следует сверить с каталогом вопросов и RIASEC-компонентом разработчика.
- При восстановлении сессии шаг уточнений восстанавливается по данным API, но для полностью точного восстановления необходимо дополнить обработку состояний.
- `recommendationId` и структура ответа generate требуют проверки на работающем API.

## Архитектура
- `app/page.tsx` — главная и основные этапы
- `app/globals.css` — редактируемые стили
- `lib/api.ts` — HTTP-клиент с X-Session-ID
- `public/assets` — отдельные фрагменты согласованного изображения и оригинальные эталоны

Для интеграции с существующим фронтендом лучше переносить визуальные компоненты и стили, а не заменять его `app/page.tsx` целиком.
