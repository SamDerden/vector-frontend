# Вектор — интерактивный профессиональный навигатор для школьников

**Вектор** — веб-приложение для знакомства школьников с интересами, профессиональными направлениями и образовательными возможностями. Проект объединяет возрастные сценарии диагностики, демонстрационные профили, рекомендации на основе ИИ и проверенного каталога, а также индивидуальный маршрут дальнейших действий.

**Публичный сайт:** https://vector-app.up.railway.app  
**Основная ветка:** `main` · **Развёртывание:** Railway · **Дата актуализации:** 11 ноября 2026 года.

> README описывает устройство и возможности кода в `main`, а не гарантирует доступность внешнего AI-шлюза, успешность каждого запроса или выдерживаемую нагрузку. Для реального запуска проверяйте состояние Railway, БД, AI и сквозные сценарии отдельно.

## Для кого и как работает

- **1–4 классы:** отдельный игровой возрастной сценарий с акцентом на интересы и доступные активности, без навязывания профессионального выбора.
- **Старшие школьники:** диагностика интересов и предпочтений, уточняющие вопросы, профессиональные гипотезы, знакомство с профессиями, пробами и образовательными возможностями.
- **Демо:** галерея 15 школьников с заранее подготовленными анкетными данными; предусмотрен путь демонстрации и прохождение сценария с уточняющими вопросами.
- **Профессиональный маршрут:** выбор гипотезы, просмотр возможностей и сохранение/отметка шагов. Наличие карточки возможности не означает, что онлайн-запись или дата мероприятия подтверждены.

Основной путь пользователя: **вход → возраст/трек или демопрофиль → диагностика → 6 уточнений → анализ → гипотезы/интересы → профиль профессии → возможности → маршрут**. Конкретные этапы зависят от возраста и доступности данных API.

## Что есть в репозитории

| Область | Реализация |
| --- | --- |
| Frontend | Next.js 15, React 19, TypeScript, адаптивные экраны |

| AI | GigaChat 2 Pro через OpenAI-совместимый корпоративный шлюз; подготовка контекста, retrieval, валидация и обработка fallback |
| RAG | Код построения/проверки индекса эмбеддингов и retrieval; фактический semantic-режим нужно подтверждать диагностикой среды |
| Генерация | Асинхронные задания, worker, восстановление результата, лимиты запросов и расхода AI |
| Безопасность | Механизмы подтверждения владения сессией и ограничений частоты запросов |
| Контент | Возрастные вопросы, 15 демоучеников, каталог профессий и связанных возможностей |
| Иллюстрации | Маскоты Снегурочка и Леший, демопортреты, изображения ответов и 30 иллюстраций профессий |

### Важное различие каталогов

В `backend/data/catalog.normalized.json` содержится **30 профессий** гибридного нормализованного набора `hybrid_v2`. В проекте также присутствуют импорт, синхронизация и дополнительные данные профессионального навигатора. **Нельзя считать эти 30 профессий полным объёмом всех исходных справочников** или автоматически приравнивать их к обсуждавшемуся расширенному каталогу на 111 профессий. При обновлениях сверяйте источник данных, версию, идентификаторы и фактическое содержимое PostgreSQL. Не переименовывайте и не удаляйте записи для «исправления» несовпадений без проверки соответствий.

## Архитектура

```text
Браузер
  └─ Frontend: app/, lib/, public/
       └─ /api → backend (через rewrite / конфигурацию)
            ├─ Сессии и диагностика
            ├─ Уточняющие вопросы
            ├─ Генерация рекомендаций и очередь заданий
            ├─ Каталог профессий / проб / образования
            ├─ PostgreSQL
            └─ AI Gateway → GigaChat / retrieval
```

Основные пути:

- `app/page.tsx` — основные пользовательские экраны и переходы;
- `app/PrimaryExperience.tsx` — отдельный возрастной сценарий;
- `app/globals.css`, `app/primary-experience.css` — оформление;
- `lib/demo-backend.ts`, `lib/session-store.ts` — интеграция и состояние пользовательского сценария;
- `lib/profession-images.ts` — соответствие названий профессий изображениям;
- `public/assets/professions/` — 30 изображений профессий;
- `public/assets/children/` — портреты 15 демоучеников;
- `public/assets/mascots/` — Снегурочка и Леший;
- `backend/app/api/` — API;
- `backend/lib/ai/` — генерация, retrieval и проверки AI;
- `backend/lib/generation-jobs.ts`, `backend/lib/generation-worker.ts` — очередь и обработка;
- `backend/migrations/` — миграции PostgreSQL;
- `backend/data/` — данные каталога, вопросы и демоданные;
- `backend/docs/` — API, передача, развёртывание и отчёты по релизам.

## Локальный запуск

Требования: **Node.js 22+**, npm, PostgreSQL (для локального backend удобно использовать Docker).

### 1. Backend

```bash
cd backend
cp .env.example .env.local
npm install
docker compose up -d db
npm run db:migrate
npm run db:seed
npm run dev
```

Backend по умолчанию доступен на `http://localhost:3000`. Укажите действительные значения `DATABASE_URL` и настроек AI в **локальном** окружении. Для Docker Compose запускайте команды из директории, где расположен соответствующий compose-файл; расположение и конфигурацию контейнеров проверяйте перед стартом.

Для демоданных, если они нужны локально: `npm run db:seed:mocks`. Операции импорта и синхронизации на production-БД требуют отдельной проверки — не запускайте их вслепую.

### 2. Frontend

В другом терминале, из корня репозитория:

```bash
cp .env.example .env.local
npm install
npm run dev
```

Frontend: `http://localhost:3001`. По умолчанию запросы `/api` проксируются на `BACKEND_INTERNAL_URL=http://localhost:3000`. При другом адресе backend измените настройки окружения.

### Проверки

```bash
# В корне: frontend
npm run typecheck
npm run build

# В backend/
npm run typecheck
npm run lint
npm test
npm run build
```

Интеграционные проверки, требующие БД и/или AI, проводите отдельно и **не направляйте тесты с записью на production**. Дополнительные сценарии находятся в `tests/`, `backend/tests/` и `backend/scripts/`.

## Railway и эксплуатация

Frontend и backend развёртываются как **разные сервисы** из одного репозитория. Backend использует PostgreSQL и требует применения миграций. Публичный адрес frontend: https://vector-app.up.railway.app.

Для корректной работы проверьте:

1. Оба сервиса собраны из ожидаемого коммита `main`, деплой имеет статус `SUCCESS`.
2. Frontend обращается к правильному backend; backend доступен по `/api/health`.
3. Секреты и адрес БД настроены **в переменных окружения Railway**, не в Git.
4. Миграции применены, данные каталога согласованы с индексом и БД.
5. AI-шлюз отвечает, генерация создаёт **непустые** рекомендации, результат сохраняется и отображается.
6. Проверены режим retrieval, обработка ошибок, восстановление заданий и изоляция сессий.
7. Перед массовой демонстрацией выполнены нагрузочные испытания с реальным профилем запросов и оценкой квоты AI.

**Важно:** лимиты и количество параллельных worker в коде могут отличаться от ранних отчётов. Источник истины — текущие `backend/lib/limited-pipeline.ts`, `backend/lib/request-limits.ts`, `backend/lib/generation-worker.ts`, конфигурация Railway и результаты нагрузочного тестирования. Число одновременно обслуживаемых пользователей нельзя выводить только из числа worker.

Подробнее: [backend/RAILWAY_DEPLOY.md](backend/RAILWAY_DEPLOY.md), [backend/docs/DEPLOY.md](backend/docs/DEPLOY.md).

## Изображения профессий

В `public/assets/professions/` находятся **30 PNG**. Функция `professionImage(title)` из `lib/profession-images.ts` сопоставляет точное название из нормализованного каталога с файлом и возвращает публичный путь. Иллюстрации выводятся в карточках гипотез и профиле профессии. Если соответствие отсутствует, используется оформление без изображения; случайная профессия не подставляется.

Для новых файлов обновляйте карту соответствий, проверяйте регистр, пробелы и названия каталога. Не меняйте идентификаторы профессий ради имени картинки.

## Безопасность и ограничения

- Проект предназначен для демонстрации и дальнейшего развития; **готовность к обработке реальных данных несовершеннолетних должна оцениваться отдельно** (согласия, политика хранения, доступ, 152-ФЗ и прочие применимые требования).
- Не коммитьте API-ключи, `DATABASE_URL`, cookie-секреты и файлы `.env.local`. Перед открытием репозитория проверяйте **всю историю коммитов**, а не только текущие файлы.
- Генерация зависит от внешнего AI-шлюза, доступной квоты, PostgreSQL и работоспособности очереди.
- Возможности из каталога не следует трактовать как подтверждённые записи, расписания или свободные места.
- Изменения AI, миграций, каталогов и возрастной логики проверяйте регрессионными тестами и сквозными сценариями.

## Принципы разработки

Сохраняем идентификаторы и происхождение записей каталога; не создаём вымышленные профессии или ссылки; разделяем гипотезу и подтверждённый факт; не смешиваем сессии школьников; не объявляем AI и RAG работающими без сквозной проверки. Изменения фиксируем в Git, проверяем сборку и только затем считаем их опубликованными после успешного деплоя.
